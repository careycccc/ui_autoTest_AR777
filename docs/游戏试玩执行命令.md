# 游戏试玩 - 执行命令手册

本文档记录游戏专项测试（登录 → 进游戏二级页面 → 选分类/厂商 → 试玩）的全部执行方式。

对应测试文件：`tests/game-entry.test.js`

---

## 一、最常用

```bash
# 单账号调试（有头浏览器，看得见过程）
node src/index.js slots MINI
```

```bash
# 多账号并发（无头，2 并发）
node src/concurrent.js slots MINI --concurrency=2
```

---

## 二、参数说明

### 位置参数

```
node src/index.js <分类> <厂商>
```

| 位置 | 含义 | 示例 |
|------|------|------|
| 第 1 个 | 游戏分类 | `slots`、`video`、`card`、`fishing`、`hot` |
| 第 2 个起 | 游戏厂商 | `MINI`、`pp elect`、`PG`、`JDB` |

- 分类不区分大小写，`slots` 会自动转成页面上的 `Slots`
- 厂商名含空格时**加不加引号都行**，第 2 个之后的位置参数会自动拼接：

```bash
node src/index.js slots "pp elect"   # 都解析成 vendor = "pp elect"
node src/index.js slots pp elect
```

### 命名参数

| 参数 | 作用 | 默认值 |
|------|------|--------|
| `--category=<分类>` | 同位置参数第 1 个 | `Slots` |
| `--vendor=<厂商>` | 同位置参数第 2 个 | 无（走预设列表） |
| `--games="A,B"` | 指定要玩的游戏名，逗号分隔 | 取厂商预设 |
| `--all` | 该厂商下**所有**游戏依次试玩 | 关闭 |
| `--concurrency=<N>` | 并发数（仅 `concurrent.js`） | `3` |
| `--limit=<N>` | 只取账号池前 N 个（仅 `concurrent.js`） | 全部 |
| `--headed` | 有头模式（仅 `concurrent.js`） | 无头 |
| `--ui` | 调试模式，不生成报告截图（仅 `index.js`） | 关闭 |

### 环境变量

| 变量 | 作用 | 默认值 |
|------|------|--------|
| `BRAND_NAME` | 测试版面 | `brand-3004` |
| `GAME_LOAD_TIMEOUT` | 单个游戏等待画面显示的上限(ms) | `60000` |
| `GAME_VENDORS` | 未指定 `--vendor` 时的候选厂商列表 | `pp,mini` |
| `GAMEPLAY_SHOTS` | 玩法关键节点截图目录，用于校准 canvas 坐标 | 关闭 |
| `ONLY_VENDOR` | 调试用，只跑指定厂商 | 关闭 |

## 三、常用场景

### 指定厂商 + 指定游戏（推荐）

```bash
node src/index.js slots MINI --games="FortuneFlow,ballonix"
```

不写 `--games` 时会用厂商预设的游戏名，`MINI` 的预设即 `FortuneFlow` + `ballonix`。

### 把某厂商下所有游戏跑一遍

```bash
node src/index.js slots MINI --all
```

> `MINI` 厂商下有 28+ 个游戏，全跑耗时很长；
> 且未登记专属玩法的游戏会走通用 canvas 玩法，遇到 DOM 类游戏（如 `dice`）
> 必然报 `未找到游戏 canvas`。这类失败会被跳过、不阻断流程。

### 不指定厂商（走预设随机 + 失败降级）

```bash
node src/index.js
```

在 `pp` / `mini` 中随机挑一个；若该厂商下所有游戏都跑不起来，
自动标记它不可用并降级到下一个，该标记跨账号共享。

### 换版面

```bash
BRAND_NAME=brand-3003 node src/index.js slots MINI
```

### 缩短等待，快速验证流程

```bash
GAME_LOAD_TIMEOUT=25000 node src/index.js slots MINI
```

### 玩法调试：输出关键节点截图

```bash
GAMEPLAY_SHOTS="reports/gameplay-debug" node src/index.js slots "pp elect"
```

会在该目录生成「进入游戏 / 初始化完成 / 加注后 / 每轮后」的截图，
用于校准 canvas 类游戏的点击坐标。

## 四、并发执行

```bash
# 2 并发跑完账号池全部账号
node src/concurrent.js slots MINI --concurrency=2

# 只跑前 2 个账号（快速验证）
node src/concurrent.js slots MINI --concurrency=2 --limit=2

# 有头模式看过程
node src/concurrent.js slots MINI --concurrency=2 --headed
```

并发说明：

- 账号来自 `data/1.txt`，一行一个，空行与 `#` 注释行忽略
- 每个账号独立 `BrowserContext`，cookie / localStorage 互不干扰
- 设备从 `iphone14 / iphone14pro / pixel7 / samsungS23` 随机分配
- 日志自动带 `[W1|1102]` 前缀（worker 号 + 账号后 4 位），便于还原单账号链路
- 厂商「不可用」的判定跨账号共享：第一个账号发现某厂商全跑不起来后，
  后续账号直接跳过它

### 账号文件格式

`data/1.txt`：

```
# 一行一个账号，密码统一 qwer1234
2026081102
918005199727
```

**12 位账号会自动拆区号**：`918005199727` → 手机号 `8005199727`、区号 `91`。
非 12 位原样使用，区号取版面配置。

## 五、npm 脚本

```bash
npm test                      # 单账号，brand-3004
npm run test:ui               # 调试模式（不出报告截图）
npm run test:3003             # 换版面
npm run test:concurrent       # 并发，默认 3
npm run test:concurrent:headed # 并发 2 + 有头
```

npm 脚本要传参数时需加 `--`：

```bash
npm run test:concurrent -- slots MINI --concurrency=2
```

## 六、厂商与玩法登记

厂商预设在 `scenarios/game/vendor-registry.js`：

```js
mini: {
    category: 'Slots',
    vendor: 'MiniGame电子',
    vendorAliases: ['MINI', 'MiniGame'],   // 站点改名时依次匹配
    mode: 'byName',
    gameNames: ['FortuneFlow', 'ballonix'],
    playOptions: {}
}
```

游戏玩法分派在 `scenarios/game/game-play.js` 的 `GAMEPLAY_BY_NAME`：

| 游戏 | 玩法 | 说明 |
|------|------|------|
| `FortuneFlow` | `playFortuneFlow` | DOM 游戏，读余额算投注额，保留 100 不动用 |
| `ballonix` | `playBallonix` | DOM 游戏，加减注按 25/50 步长调整 |
| 其他 | `playSlotGame` | canvas 游戏，按相对坐标点击旋转 |

未登记的游戏一律走通用 canvas 玩法。

## 七、排查

| 现象 | 原因与处理 |
|------|-----------|
| `未找到厂商「X」，当前可选: ...` | 站点改了厂商显示名，在 `vendorAliases` 里补别名 |
| `未找到分类「Slots」，当前可选: `（空） | 页面未渲染完，已内置 15s 等待，仍空则检查是否停在非二级页面 |
| `点击游戏入口被遮挡` | 全屏强制弹窗，日志会打印遮挡层结构；已内置多策略清理 |
| `未找到游戏 canvas` | 该游戏是 DOM 类，需在 `GAMEPLAY_BY_NAME` 登记专属玩法 |
| `可动用资金不足` / `余额不足最小投注` | 账号没钱，需充值 |
| `密码登录：3 秒内路由未变化` | 该账号密码不是 `qwer1234`，会自动回退验证码登录 |
